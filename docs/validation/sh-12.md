# SH-12 — Taxonomie et synonymes

Administration du dictionnaire global de l'installation : création et modification
des noms, catégories et alias ; fusion explicite source vers cible avec justification.
La casse, les espaces et Unicode NFKC sont normalisés, sans rapprochement flou,
suppression de ponctuation ni déduction entre technologies. Java ne devient ni
JavaScript ni Spring Boot. Les collisions (y compris entre nom et alias) sont
refusées ; une fusion doit être décidée séparément. Retirer un alias se fait en
modifiant sa liste ; les versions antérieures restent conservées.

Les mutations sont réservées à ADMIN, revérifié sous verrou utilisateur, protégées
par CSRF, If-Match et verrou du dictionnaire. Lecture par utilisateur authentifié ;
historique réservé à ADMIN et paginé par 25. Le dictionnaire ne contient aucun CV.
Maximum 1 000 compétences, 50 alias chacune, noms/alias de 200 caractères. La lecture
renvoie ce dictionnaire borné complet ; aucune recherche hybride n'est revendiquée.

À chaque nouvelle publication humaine, les compétences validées sont associées par
égalité exacte à un snapshot du dictionnaire. Le libellé retenu, l'identifiant et le
nom canonique, la version et le source_index sont conservés par révision ; le brut
et les preuves restent dans sa source SH-09. Une inconnue reste inconnue. Les
anciennes publications ne sont pas recalculées ; une nouvelle publication est
nécessaire pour appliquer un dictionnaire modifié. Une fusion conserve les anciens
snapshots et transfère les noms/alias de la source vers la cible, sans cycles.

Interface : Administration → Compétences. Créer PostgreSQL, puis publier une
compétence « Postgresql » : « Appellations de la publication » affiche le lien
Postgresql → PostgreSQL et la version. Le dictionnaire est vide à l'installation ;
aucun lexique tiers ni licence externe ajouté.

Vérification : `TaxonomyTest` couvre droits, CSRF, concurrence, collisions,
normalisation exacte et fusion ; `HumanReviewTest` couvre le gel de la
normalisation après modification et le refus inter-périmètre. La CI exécute ces
tests avec PostgreSQL et toutes les migrations. Les contrôles navigateur sont
complétés pour le parcours d'administration ; leur résultat est à vérifier en CI.
