# SH-07 — Antivirus et extraction texte

## Parcours livré

Une réception S3 durable crée une tâche PostgreSQL dans la même transaction que sa mise en quarantaine (V5). La migration programme aussi les anciennes réceptions non expirées. Le backend réserve un bail de quatre minutes, transmet les octets au worker privé, puis persiste le résultat seulement si le bail, la source, l'échéance et l'habilitation du demandeur restent valides. Une seule tâche par document ; trois tentatives maximum, attente de 60 puis 120 secondes et relance humaine des seuls échecs techniques. Une suppression en vol ne recrée aucune ligne.

Le worker vérifie SHA-256, consulte la version ClamAV, scanne par INSTREAM, puis revérifie la version des signatures. Indisponibilité, réponse inattendue, changement de signatures durant le scan ou signatures de plus de 72 heures bloquent le parsing. La version antivirus complète et la version du pipeline sont conservées. Un rejet antivirus/documentaire ne peut pas être relancé pour contourner le contrôle : fournir une nouvelle version corrigée.

Formats : Markdown UTF-8 ; DOCX paragraphes/tableaux/cellules physiques fusionnées et en-têtes/pieds de page ; PDF texte par page ; DOC ancien converti en texte par antiword, sans exécution Office. Le DOC avec champs, macros, objets incorporés ou chiffrement n'est pas pris en charge et doit être remplacé. L'extraction DOC ne reconstruit pas les coordonnées de cellules ; sa preuve est `legacy-document`. Ce compromis explicite évite d'attribuer des coordonnées inventées.

Les pages PDF sans texte sont signalées `OCR_REQUIRED` : leur OCR relève de SH-08. Les PDF mixtes contenant du texte et des images sur une même page ne font pas encore l'objet d'une détection régionale d'OCR. Les images Word ne sont pas OCRisées. La structure professionnelle et la revue relèvent de SH-09/10 : texte brut non validé, aucune fiche, aucun index et aucun score créés ici. Une note 2,5 reste du texte, jamais une durée déduite.

`GET /api/v1/imports/{id}/analysis` retourne statut et preuves textuelles, exclusivement dans le vivier autorisé et avant échéance ; consultation auditée. `POST .../analysis/retry` exige session/CSRF et droits actuels. L'interface propose consultation, actualisation et relance technique. Le texte est rendu par React comme texte, jamais comme HTML ou Markdown exécuté. Les originaux restent privés en quarantaine, même après extraction.

## Isolation et limites

- Worker non-root, conteneur en lecture seule, capacités retirées, `no-new-privileges`, réseau Docker interne, 768 Mio/1 CPU/32 processus, temporaires tmpfs nettoyés à chaque tâche.
- Parseur enfant : filtre seccomp Linux refusant création/usage de sockets et ptrace, 512 Mio d'espace virtuel, 20 s CPU, 25 s temps réel, sortie 4 Mio, 32 descripteurs. Le filtre est hérité par antiword ; indisponible = aucun parsing. Aucun secret transmis dans l'environnement du parseur.
- Document 15 Mio ; DOCX 1 000 entrées/40 Mio décompressés/8 Mio par entrée/ratio 100 ; PDF 100 pages ; résultat 500 000 caractères/5 000 blocs. Les XML avec entités sont refusés ; références externes et contenus actifs pris en charge par les contrôles sont refusés.
- Les erreurs HTTP et logs techniques n'incluent ni contenu CV ni token. Les métriques/file morte administrable complète restent SH-36.
- Cette isolation réduit l'exposition mais ne certifie pas l'absence de vulnérabilité des parseurs. Les paquetages système sont fournis par Debian bookworm ; leur inventaire effectif doit être conservé avec l'image déployée.

## Vérifications reproductibles

```sh
python3 -m venv .venv
.venv/bin/pip install -r services/document-worker/requirements.txt
.venv/bin/python -m unittest discover -s services/document-worker/tests -v
mvn -f services/api/pom.xml test
npm --prefix apps/web run build
python3 scripts/check_foundation.py
```

Linux avec libseccomp2 requis pour le test d'isolation. Les tests unitaires worker simulent le verdict antivirus pour vérifier l'ordre des contrôles ; ils ne remplacent pas le test réel. La CI lance ClamAV et le worker Docker puis `scripts/smoke_analysis.py` : OIDC/S3/ClamAV/extraction, chaîne EICAR synthétique rejetée, accès hors vivier et CSRF. Les parcours navigateur vérifient consultation du texte à 1 280 et 320 px avec texte 200 %. Les tests Java couvrent révocation, expiration, bail remplacé, disparition du document, intégrité, résultats invalides et reprises bornées.

Aucun benchmark de qualité OCR/IA ni recette sur CV réels n'est revendiqué.
