# SH-28 — Paramètres et template versionné

## Comportement livré

L’administrateur publie des limites d’admission sans modifier le code. Chaque version contient les valeurs, la date, l’auteur, un motif et la référence du modèle Word propre. La publication contrôle les bornes côté serveur, exige CSRF et If-Match, puis conserve l’ancienne version dans un historique paginé. Aucun secret ou inventaire de l’environnement n’est renvoyé.

| Paramètre | Initialisation | Bornes |
|---|---|---|
| Taille par fichier | 15 Mio | 1 octet à 15 Mio |
| Fichiers par lot | 100 | 1 à 100 |
| Taille totale du lot | 300 Mio | Taille par fichier à 300 Mio |
| Fichiers par compte | 1 000, ou environnement initial | 1 à 100 000 |
| Octets par compte | 3 000 Mio, ou environnement initial | 1 octet à 1 Tio |

Les quotas cumulent tous les viviers et les réservations, y compris celles encore incomplètes. La configuration persistée prévaut ensuite sur l’environnement. Les plafonds de sécurité multipart, analyse et décompression ne sont pas administrables ici.

Une nouvelle réception ou un manifeste réserve la version courante dans la même transaction que le contrôle des quotas. Une reprise idempotente conserve cette référence. Les fichiers d’un lot conservent celle du manifeste, même après baisse de taille, nombre ou quota. Les documents reçus avant V29 restent explicitement sans référence historique ; les anciens lots utilisent les plafonds techniques antérieurs. La baisse des limites n’efface ni ne requalifie les travaux existants. Les contrôles d’accès, d’expiration et de contenu continuent à s’appliquer lors d’une reprise.

Le membre d’un vivier consulte les limites courantes sans motif ni auteur. L’accès administrateur n’accorde aucun accès supplémentaire aux documents. L’écran des réceptions affiche la version réservée.

## Modèle nettoyé

Le téléchargement administrateur publie uniquement `skillhunters-cv-template-v1.docx`, déjà nettoyé et qualifié dans SH-11. L’original n’est pas exposé. Le SHA-256 du téléchargement correspond à la référence de configuration ; chaque export conserve aussi son modèle et son empreinte. Aucun octet du modèle n’est modifié par SH-28. Une nouvelle version du modèle reste une livraison qualifiée avec rendu et inspection, pas un téléversement libre en production.

## Vérifications

```sh
mvn -f services/api/pom.xml test
npm --prefix apps/web run build
python3 scripts/check_foundation.py
git diff --check
# Stack compose démarrée, DEMO_PASSWORD chargé :
npm --prefix apps/web run test:browser
```

La suite Java compte 200 tests : nouveaux imports sous nouvelles limites, reprise d’une réception interrompue, lot réservé avant baisse de quotas et taille, ancien lot sans référence inventée, bornes, rôles/viviers, CSRF, versions concurrentes, historique paginé et empreinte du modèle. En local H2, 3 tests d’intégration restent conditionnels ; la CI active les recettes PostgreSQL, SMTP, benchmark et S3.

Deux parcours navigateur supplémentaires utilisent les vrais endpoints et OIDC : publication, historique, téléchargement et restauration des limites initiales, à 1280 et 320 px (texte à 200 % sur mobile). Ils portent la suite à 19 parcours. Leur résultat est contrôlé dans la CI de la PR, avec les migrations V1–V29 sur PostgreSQL. Le build frontend et les contrôles de contrat sont exécutés séparément.

## Limites

Cinq paramètres d’admission sont administrables ; les secrets, connexions, modèles d’extraction et paramètres de sécurité worker restent hors de cette API. L’historique est borné à 10 000 versions. L’auteur est enregistré par identifiant, sans copie du profil. Les motifs doivent rester factuels et sans donnée candidat. Un seul modèle Word qualifié est disponible dans cette livraison.
