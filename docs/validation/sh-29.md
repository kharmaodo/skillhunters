# SH-29 — Exploitation locale et Docker

Les procédures exécutables sont dans [operations.md](../operations.md). Deux modes sont testés : stack Docker complète et Java/Vite hôte avec infrastructure Docker. Les images externes sont épinglées par digest résolu le 17 novembre 2026 auprès de Docker Registry/Quay ; MinIO est construit depuis un commit vérifié. Les ports restent loopback et les secrets initiaux sont générés aléatoirement sans écrasement d’installation.

Le snapshot cohérent sous arrêt des écrivains contient PostgreSQL applicatif, Keycloak et les versions du bucket privé. Les documents doivent correspondre à leurs SHA-256. Le manifeste et son expiration sont authentifiés par HMAC avec une clé conservée séparément ; l’enveloppe a également un contrôle d’intégrité. L’archive n’est pas chiffrée par l’outil : stockage chiffré et privé obligatoire pour l’exploitation.

La restauration exige deux bases et un bucket vides, une sauvegarde valide et le journal courant indépendant. Aucun journal ancien n’est restauré. Les nouvelles installations isolent celui-ci dans un service/volume et des identifiants distincts ; les installations existantes gardent leur endpoint historique jusqu’à une migration explicite. Le rapport final distingue le staging de la réussite après rejeu et purge. Les traces contiennent versions d’images/migrations et compteurs, sans CV ni secret.

## Vérifications

- 18 tests Python : signature, modification des octets/métadonnées, expiration signée, archives hostiles, cohérence DB/objet, refus des cibles occupées, attente de purge des sources expirées, secrets et invariants des images/ports.
- Suite Java : 201 tests, dont deux intégrations S3 conditionnelles ; le nouveau test vérifie un journal sur un endpoint séparé après disparition du bucket source.
- CI complète : migrations PostgreSQL, 19 parcours navigateur existants, puis snapshot réel, demande d’effacement postérieure, suppression contrôlée des seuls volumes métier synthétiques, restauration sur volumes neufs, SHA-256 et anciennes versions, rejeu du journal, connexion OIDC et mode Java/Vite hôte avec nouvel import.
- Contrats et whitespace : `python3 scripts/check_foundation.py`, `git diff --check`.

La recette destructrice est réservée au projet synthétique GitHub Actions. L’exploitation normale ne détruit aucun volume et n’écrase aucune cible. Les limites restent explicites : mono-instance, arrêt pour snapshot, journal à répliquer hors machine, pas de qualification publique HTTPS/HA, pas de stockage WORM garanti par le Compose et pas de RPO/RTO contractuel. La migration automatique d’un journal historique vers un autre fournisseur n’est pas incluse.
